# بوابة التحقق

شغّل `npm run check` من نسخة المصدر على Node.js 22.16 أو أحدث بعد تثبيت الاعتمادات. تنفّذ البوابة TypeScript وكل ملفات `tests/**/*.mjs` تلقائيًا، إلا الاستثناءات المحددة بسبب واضح في `check-manifest.json`. إضافة اختبار جديد لا تحتاج تعديل قائمة تشغيل. العمليات متتابعة، بحد ذاكرة JavaScript قدره 512 MiB للاختبار و768 MiB لفحص الأنواع؛ هذه ليست حدودًا لإجمالي ذاكرة نظام التشغيل.

النتيجة التفصيلية في `output/check/default-results.json`، وسجل مستقل لكل اختبار. أي فشل يجعل الأمر يفشل. لا توجد إعادة محاولة تخفي فشلًا. الاختبارات تستخدم بيانات مصطنعة وقواعد مؤقتة؛ نجاحها لا يعني اختبار الهاتف أو بيانات الإنتاج أو PostgreSQL. التطبيق الحالي واختبارات الاستضافة المحمولة يستعملان SQLite، وليس PostgreSQL.

## فحوص منفصلة لها متطلبات إضافية

- **ملف ERP الأصلي:** `ERP_TEST_WORKBOOK=/absolute/path/original.xlsx npm run check:erp`. لا تعتبر هذه البوابة ناجحة دون تشغيلها بالملف الأصلي الذي تتوقعه الاختبارات. عند غياب الملف يفشل الأمر قبل الاختبارات. الاختبارات الصناعية الأخرى للمبيعات وKPIs تعمل ضمن البوابة الافتراضية.
- **بناء الإصدار:** بعد `npm run build`، شغّل `node tests/app-update-release.mjs` و`node tests/namecheap-http.mjs` و`node tests/production-load.mjs` على جهاز مراجعة مناسب. هذه تختبر النسخة المبنية محليًا؛ لا تنشر الموقع.
- **المتصفح:** الاختبارات المصنفة `browser` تحتاج Playwright ومتصفحًا متاحًا، ومعظمها يحتاج البناء المستقل. شغّلها صراحة بعد تجهيز متطلباتها. الاختبارات الافتراضية التي تحمل `ui` تستخدم مكونات حقيقية مع بيئة hooks/DOM مضبوطة، وليست تجربة متصفح كامل.
- **حزم التثبيت:** اختبارات Python و`package-install.mjs` تحتاج حزمة إصدار فعلية حسب واجهة كل اختبار. لا تمرر مصدر المشروع بدل الحزمة. `app-update-preview.mjs` مولّد معاينة وليس اختبار نجاح.
- **Android:** فحوص `mobile/android` وبناء APK وتثبيته على جهاز تبقى بوابة مستقلة تحتاج JDK/Android SDK والتوقيع المناسب. لا تعتبر أي نتيجة JavaScript دليلًا على نجاح التثبيت أو عمل GPS في الخلفية.

## إصلاحات تجهيز الاختبارات

تم تحديث توقعات قديمة فقط لتوافق سياسات المصدر الحالية: المدير يقدر يحذف الزيارة، والمندوب يعدّل بيانات العميل لكن لا يعدّل أو يحذف الزيارات؛ عدم وجود احتياج لا يملأ صنفًا افتراضيًا؛ والأدلة المحفوظة بدون شبكة لا تنتهي بعد48 ساعة. تم تصحيح تاريخ إنشاء حساب fixture قبل فترة تتبعه، والمحافظة على رفض البيانات خارج اليوم والصلاحية والترتيب.

كذلك تم استكمال mock لـ`useRef` والتخزين دون شبكة، واختيار اشتراك الشاشة بدل افتراض ترتيب effects، واختبار اختيار المنطقة بالراديو، وتحديث نصوص الواجهة وعدد migrations. اختبار migration-manifest يشغّل منطق التجميع الحقيقي مع stub لبناء الواجهة، ولا يدّعي بناء التطبيق بالكامل. هذه تعديلات بنية اختبار، ولا تُحسب كإصلاحات أمان في المنتج.

## اختبارات النسخة المبنية الجديدة (بوابة `release-build`)

تشغّل النسخة المبنية `dist/standalone` عبر HTTP على قاعدة SQLite مؤقتة وبريد وهمي، بالأداة المشتركة `scripts/lib/built-app.mjs`. نفّذ `pnpm build` أولًا ثم:

| الأمر | ما يثبّته |
|---|---|
| `node tests/server-authorization.mjs` | المجهول يحصل على 401 في كل المسارات المحمية؛ مصفوفة الأدوار؛ نطاق العملاء والزيارات والفواتير لكل دور؛ تجميع المشرف والمدير؛ رفض كتابات المندوب |
| `node tests/sales-date-boundaries.mjs` | فلتر الشهر والتواريخ: اليوم الكبيس، حدود الشهور والسنوات، السجلات القديمة، التواريخ غير الصحيحة والمستقبلية |
| `node tests/visit-files-http.mjs` | رفع المرفقات وتنزيلها: النوع من المحتوى، الحجم، عزل المناطق، إعادة الرفع المتطابقة |
| `node tests/targets-attainment-http.mjs` | معادلة التحقق الموزون للمستهدف، استبعاد الأصناف ذات المستهدف صفر، تجميع المشرف والمدير، من يملك تعديل الأوزان والمستهدفات |

مع `tests/namecheap-http.mjs` و`tests/app-update-release.mjs` تُكوّن هذه الاختبارات بوابة فحص الإصدار المبني. لا تُشغَّل ضمن `pnpm check` لأنها تحتاج بناءً.

## تشغيل اختبارات المتصفح في بيئة معزولة

```bash
export CODEX_PRIMARY_RUNTIME_NODE_MODULES=/path/to/node_modules   # يحتوي playwright
export YR_BROWSER_EXECUTABLE=/path/to/chromium
env -u HTTPS_PROXY -u https_proxy NO_PROXY='*' \
  YR_COMPETITORS_SCREENSHOT_DIR=/tmp/shots YR_COMPETITORS_REPORT=/tmp/report.json \
  node tests/competitors-browser.mjs
```

- عطّل متغيرات الوكيل (proxy) وإلا تُعاد الاتصالات إلى المضيف المحلي.
- وجّه مخرجات الأدلة إلى مجلد مؤقت بمتغيرات `YR_*_SCREENSHOT_DIR` و`YR_*_REPORT`؛ بعض الاختبارات تكتب افتراضيًا فوق ملفات الأدلة داخل `docs/`.
- `tests/offline-browser.mjs` و`tests/pwa-browser.mjs` و`tests/app-browser-workflows.mjs` تحتاج متصفحًا يطبّق محاكاة انقطاع الشبكة ورفض إذن الموقع على عامل الخدمة والسياق الافتراضي (وضع المتصفح عبر CDP بمتغير `YR_BROWSER_CONTENT_SHELL=1`). في Chromium العادي عبر Playwright تتوقف عند خطوة الإقلاع البارد دون اتصال وخطوة رفض الإذن؛ هذا قيد في أداة المحاكاة وليس في التطبيق (راجع `docs/qa/REPORT-AR.md`).
- `tests/erp-sales-browser.mjs` يحتاج ملف ERP الأصلي (`ERP_TEST_WORKBOOK`).
