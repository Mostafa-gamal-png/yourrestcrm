# إصلاح تعديل العملاء — يورست CRM

المشكلة مؤكدة من الكود ومن تجربة الحزمة السابقة: المندوب يحاول تحديث جوال أو لوكيشن عميل في منطقته، لكن الحفظ يرد بـ403 ورسالة «المندوب خارج نطاق منطقتك» إذا كان المسؤول الحالي عن العميل مديرًا عامًا خارج قائمة منطقته. وكان مدير المبيعات لا يستطيع فتح تعديل بعض بطاقات العملاء المرتبطة بالإدارة. وجود مسؤول قديم غير نشط كان يمنع تصحيح البيانات أيضًا.

## ما تغير

- يستطيع المندوب ومدير المبيعات تصحيح بيانات العملاء المتاحين داخل نطاق المنطقة، بما فيها الجوال واللوكيشن.
- حفظ التفاصيل يحتفظ بالمسؤول والفرع المسجلين، حتى إذا لم يعد المسؤول ضمن قائمة الاختيار. لا ينقل العميل تلقائيًا إلى من ضغط حفظ.
- الخريطة والاتجاهات تستخدم الإحداثيات الجديدة بعد الحفظ.
- تغيير المسؤول أو الفرع أو المنطقة يظل خاضعًا للصلاحيات والتحقق الأصليين. حقول التكليف تظهر للقراءة فقط عندما لا توجد صلاحية تغييرها.
- صلاحيات المشرف المرتبطة بفريقه، وحذف العملاء، وإضافة الماكينات، وقراءة الزيارات السابقة لم تتوسع.
- التحقق عند الكتابة يمنع الحفظ إذا تغير دور المستخدم أو منطقته أو حالة حسابه أو إصدار السجل أثناء الطلب.

## نتيجة التحقق

| الفحص | النتيجة |
| --- | --- |
| اختبار الانحدار على الكود القديم | فشل كما هو متوقع: 403 بدل 200 |
| نفس السيناريو على الإصلاح | نجاح، مع بقاء المسؤول والفرع كما هما |
| اختبارات API وقاعدة SQLite معزولة | 207 تحققات ناجحة |
| اختبارات مكونات الواجهة | 132 تحققًا ناجحًا |
| متصفح Chromium حقيقي بعرض 360 بكسل | 54 تحققًا ناجحًا؛ حفظ المندوب والمدير وتحديث الخريطة |
| HTTP على الإصدار المبني | 381 تحققًا ناجحًا |
| بيانات تحديث تطبيق Android وملف APK | 14 تحققًا ناجحًا؛ ملف APK لم يتغير |
| `npm run check` | 95 من 95 مجموعة فحص ناجحة، بما فيها TypeScript |
| أداة التفعيل والنسخة الاحتياطية | 55 تحققًا جديدًا و69 تحققًا موروثًا؛ HTTP لهذا الاختبار محاكى |
| ملفات الحزمة وموارد وضع عدم الاتصال | تطابق بصمات 2848 ملف تشغيل و14 موردًا |

اختبار المتصفح أعاد إظهار الرفض على الحزمة القديمة، ثم نجح على البناء الجديد. لا أخطاء JavaScript ولا تجاوز أفقي في الشاشات المختبرة. البريد وGPS وبيانات العملاء في الاختبارات مصطنعة ومحلية؛ لم تُستخدم قاعدة الإنتاج ولم يُختبر هاتف فعلي.

لا توجد هجرة جديدة لقاعدة البيانات: التحديث يستهدف النسخة ذات 15 هجرة المفعّلة في 7 أكتوبر 2026. حزمة التفعيل تحتفظ بالإعدادات والبيانات وتستخدم نسخة احتياطية واحدة لليوم بتوقيت السعودية. تنشئ نسخة كاملة فقط عندما لا توجد نسخة سليمة لليوم، وتتحقق من بيانات ما قبل كل تحديث بصورة مستقلة عن النسخة اليومية. إعداد الحزمة واختبارها محليًا لا يعنيان نشرها؛ يلزم تنفيذ التفعيل ثم التحقق على الاستضافة.
