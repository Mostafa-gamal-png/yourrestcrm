تحديث يورست CRM — المُفعِّل يوقف التطبيق بنفسه إن أعاد المضيف تشغيله (2026-10-27)

الحزمة تخص crm.yourrest.org فقط. لا تحتوي إعدادات ولا بيانات تشغيل ولا حسابات ولا مفاتيح، ولا APK جديدًا (أندرويد 1.0.10 / code 11 كما هو).
لا ترحيل جديد: قاعدة البيانات تبقى 16 ترحيلًا كما هي الآن. لا يتغير أي جدول ولا أي بيانات، ولا يمس هذا التحديث تسجيل الدخول ولا الجلسات.
لا تشغّل setup.cjs ولا تنسخ الملفات فوق التطبيق الحالي ولا تعدّل settings.cjs أو مجلد البيانات yourrest-crm-data.
الرفع والفحص يمكن تنفيذهما والتطبيق يعمل. يلزم إيقاف يورست فقط أثناء تبديل مجلد release والتحقق؛ لا توقف أي تطبيق آخر.
هذه الحزمة تشمل كل ما في حزمة «أعد التحميل» التي رفعتها وكل ما قبلها. لها مجلد رفع واسم مُفعِّل جديدان؛ لا تستخدم مجلدات الحزم السابقة ولا تحذفها.
ملاحظة: اليوم يوم جديد بتوقيت السعودية، فالمُفعِّل سيأخذ نسخة احتياطية كاملة جديدة قبل التبديل (خطوة 2/4)، وقد تستغرق دقائق أطول من المعتاد.

ما الذي يتغيّر
1. لا تغيير يراه المندوب أو الموظف في التطبيق: الإصدار نفسه الذي رفعته آخر مرة، والتغيير كله في أداة التحديث (المُفعِّل) المرفقة بالحزمة.
2. المشكلة التي نحلّها: بعد Stop App كان مضيف cPanel يعيد تشغيل التطبيق لوحده كلما وصله طلب (تتبع المناديب يرسل طلبات طوال النهار)، فيظهر STOP APP_OR_DATA_STILL_IN_USE وتضطر لأمر kill ثم المُفعِّل فورًا.
3. الحل: المُفعِّل نفسه يوقف عملية خادم Node.js الخاصة بالتطبيق (lsnode أو node) إن وجدها تعمل، بإنهاء هادئ أولًا ثم بالقوة لمن لم ينتهِ، ويكرر حتى ثلاث مرات إن أعاد المضيف تشغيله. يطبع «APP STILL RUNNING (PROCESS ...): STOPPING IT NOW...» ثم «APP PROCESSES STOPPED: n». ظهور هذين السطرين طبيعي وليس خطأ.
4. حدود الأمان: لا يوقف إلا خادم Node.js الذي يمسك مجلد التطبيق أو مجلد البيانات؛ لا يمس الطرفية التي شغّلته ولا برنامجًا آخر (مثل صدفة جالسة في المجلد أو سكربت فحص). إن بقي برنامج كهذا يمسك المجلد فيظهر STOP APP_OR_DATA_STILL_IN_USE كما كان ولا يتغير شيء.
5. يعمل في الخطوة الأولى فقط (قبل أي قفل أو نسخة)، ولا يعمل مع --check ولا --verify. الفحوص اللاحقة داخل التبديل تبقى صارمة: إن أعاد المضيف تشغيل التطبيق وسط التبديل فيتوقف بخطأ ولا يتغير شيء في الإنتاج قبل لحظة التبديل نفسها.
6. أُضيف إلى المُفعِّل اسم تحديث «أعد التحميل» (update-reload-notice-activation-20261021) ليعيد استعمال نسخة اليوم الاحتياطية إن لزم.

الخطوات

1. نسخة احتياطية لليوم: يأخذها المُفعِّل في الخطوة 4 دون تدخل منك. لا تنفذ شيئًا هنا.

2. والتطبيق يعمل، ارفع الحزمة وافكها داخل:
/home/youriedx/yourrest-crm-update-auto-stop-20261027
يجب أن يظهر مجلد release والملف yourrest-activate-update-auto-stop.cjs مباشرة داخل هذا المسار. (مجلد جديد غير مجلدات الحزم السابقة؛ لا تفكّ فوق أي مجلد قديم.)

3. افحص الحزمة دون إيقاف التطبيق:
cd /home/youriedx && /opt/alt/alt-nodejs22/root/usr/bin/node /home/youriedx/yourrest-crm-update-auto-stop-20261027/yourrest-activate-update-auto-stop.cjs --check

يجب أن يظهر PACKAGE AND CONFIGURATION: READY، ولا يظهر سطر SCHEMA CHANGE لأن لا ترحيل في هذه الحزمة. إن ظهر STOP فلا تكمل، واحتفظ بالناتج وأرسله لي.

4. عند الجاهزية، اضغط Stop App لتطبيق يورست فقط، ثم نفّذ مباشرة (لا حاجة للانتظار ولا لأمر kill):
cd /home/youriedx && /opt/alt/alt-nodejs22/root/usr/bin/node /home/youriedx/yourrest-crm-update-auto-stop-20261027/yourrest-activate-update-auto-stop.cjs

الأمر يوقف ما أعاد المضيف تشغيله (إن وجد)، ويفحص البيانات الحالية (يجب أن تكون 16 ترحيلًا؛ غير ذلك يتوقف دون تغيير)، ويأخذ نسخة اليوم الكاملة (دقائق)، ثم يبدّل مجلد release.
إن ظهر STOP APP_OR_DATA_STILL_IN_USE فهناك برنامج آخر (غير خادم التطبيق) يمسك مجلد التطبيق أو البيانات، مثل طرفية مفتوحة داخل مجلد yourrest-crm أو سكربت فحص يعمل. أغلقه وأعد الأمر نفسه؛ لم يتغير شيء. للبحث عنه: ps -u youriedx -o pid,etime,args

5. عند ظهور START APP IN CPANEL اضغط Start App، ثم:
cd /home/youriedx && /opt/alt/alt-nodejs22/root/usr/bin/node /home/youriedx/yourrest-crm-update-auto-stop-20261027/yourrest-activate-update-auto-stop.cjs --verify

النجاح النهائي: DEPLOYMENT VERIFIED، وقبله MIGRATIONS: 16 / DATABASE: OK / CUSTOMER CODES: OK وسطر LOGIN HTTP: 200 / ANONYMOUS CRM API: 401 / /api/support: 401 / /api/complaints: 401 / /api/complaint-report: 401 / /api/service-kpi: 401.
لا يظهر MIGRATION APPLIED لأن لا ترحيل. إن ظهر STOP فاحتفظ بالناتج وأرسله لي قبل أي خطوة أخرى.

6. بعد النجاح جرّب:
- افتح crm.yourrest.org وسجّل الدخول (دخولك الحالي يبقى كما هو؛ التحديث لا يمس الجلسات) وتصفّح العملاء.
- المندوبون الذين فتحوا التطبيق قبل التحديث الماضي يرون شريط «يوجد تحديث للتطبيق» من الإصدار الماضي، وهذا الإصدار لا يغيّر ملفات الواجهة، فلن يظهر لهم شريط جديد بسببه.

إذا ظهر STOP أو أي خطأ: احتفظ بالناتج للمراجعة. لا تمسح ملفات الحالة أو القفل ولا تسترجع بيانات قديمة ولا تكرر التبديل قبل مراسلتي.

التراجع (لا تنفذه قبل أن تراسلني)
هذا التحديث لا يغيّر شكل قاعدة البيانات ولا البيانات، فالتراجع هو إعادة مجلد release القديم فقط، في أي وقت:

2) cd /home/youriedx/yourrest-crm && mv release release-failed-20261027-autostop && mv /home/youriedx/yourrest-update-auto-stop-activation-20261027-XXXXXX/old-release release

التراجع لا يفقد بيانات؛ يعود التطبيق كما كان.

ملاحظات تشغيل
- هذا أول تحديث يحمل الإيقاف التلقائي، فالتحديث نفسه هو أول استعمال له. التحديثات القادمة تستفيد منه بالطريقة نفسها.
- المُفعِّل لا يوقف شيئًا في --check أبدًا، ولا يعدّل قاعدة البيانات ولا الإعدادات ولا الملفات المرفوعة.
